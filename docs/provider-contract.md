# Provider contract

Top-level and managed profiling share `OwnedRuntimeProcess` for bounded capture and shutdown. Without psutil, the top-level provider can control only its direct child and reports unavailable telemetry; managed profiling refuses to invent PID/start proof. Observed detached sessions fail with `EPROTO`; observed descendant scope remains partial because discovery/cleanup sampling is not exhaustive OS containment. Subject/probe/workload and cleanup deadlines are bounded, primary failures survive secondary shutdown failures, and stream bodies remain restricted local artifacts. Portable evidence includes hashes, byte counts, truncation, and step statuses. These are unreleased convenience façades, not separate compatibility contracts.

Phase 4P's `standalone-pstats` service is offline and runs no target code. It reads unchanged, bounded profile bytes through a tool-owned worker, rejects malformed metrics, preserves unresolved caller-only nodes, and validates all retained counts/timings after portable reload. `managed-cprofile` is an explicit execution service requiring authorization and direct subject PID/start/nonce/profile-digest checks; supplied sidecars alone are not independent proof. Missing identity, forced termination, malformed serialization, and unavailable graphics never become successful empty evidence. Darwin address-space limiting and the remaining managed lifecycle/provider qualification work are disclosed in [current scope and roadmap](roadmap.md).

## Language and nomination adapters

Language front ends declare parsing, provenance, spans, symbols, dependencies, calls, control flow, data flow, exceptions, effects, contracts/shapes, clone normalization, test discovery, and coverage-binding capabilities as `supported`, `partial`, `unsupported`, or `unavailable`. Each language/section contribution validates independently. A failed contribution retains validated source, module, and parser provenance while excluding malformed downstream records and making completeness explicit.

The Ruby front end invokes the configured Ruby 3.3+ executable with the bundled Prism-to-JSON driver using an argument array and source bytes on standard input. The driver never loads target Ruby. Timeout, nonzero exit, malformed JSON, parser errors, and source changes are distinct failures. Portable reports retain bounded Ruby/Prism identities, not the executable path.

The semantic nomination provider is disabled by default and accepts only an existing absolute local model directory. Loading is lazy with local-files-only and remote-code disabled. The provider stores content/configuration/license hashes and bounded metadata, never the host path. Embeddings nominate bounded pairs only; deterministic structural, behavioral, contract, effect, and ownership evidence remains authoritative.

Providers implement `AnalysisProvider`, exposing `availability(context)` and `run(context)`. Availability and result values are strict Pydantic models; provider implementations may use frozen dataclasses internally.

Language front ends are a separate internal protocol. They consume immutable `SourceUnit` values and return normalized immutable facts, diagnostics, provenance, bounds, and completeness; parser nodes never cross that boundary. The Python front end uses the standard library. The optional JavaScript front end lazily imports pinned Tree-sitter bindings, records grammar ABI/version in portable provenance, and never invokes Node, npm, package scripts, loaders, or target code.

External commands use argument arrays, no shell interpolation, a bounded environment, captured byte output, and a timeout. Results retain executable identity, version when available, exit status, duration, stdout/stderr SHA-256, normalized observations, diagnostics, state, and completeness.

An executable that is absent is `unavailable`. Timeout is `timeout`; a nonzero exit is `nonzero`; syntactically or structurally invalid output is `malformed`. All are incomplete and retain diagnostics. None may be represented as a successful empty observation list.

Unified scans expose native AST, contract, dictionary, validation, topology, clone/commonality, state/side-effect, cohesion, test-impact, and optional Git provider states. Git unavailability is optional and does not make an otherwise complete static scan incomplete. Missing test roots are also optional/unavailable; discovered malformed tests are failed evidence.

Coverage and runtime providers are never invoked by a static scan. `coverage-run` and `profile` require `--allow-execution`, use argument arrays, a conservative allowlisted environment, a new owned process session, bounded timeout cleanup, and local-only stdout/stderr. `coverage-import` uses coverage.py's public API or a strict JSON contract and records source mismatch as partial/unbound. `stdlib-cprofile` remains usable when optional psutil telemetry is unavailable; the resource provider then reports `unavailable` rather than zero-valued success.

The required Phase 4P cProfile expansion keeps offline ingestion and managed execution as different provider operations. Offline ingestion reads unchanged artifacts only through `pstats.Stats`. Managed execution consumes a validated redacted run specification, supports `python-module` and explicitly instrumented `application-managed` subjects, profiles the actual subject rather than its harness, proves PID/start identity, and waits for graceful shutdown and profile serialization before report assembly. It never uses `shell=True`, hidden injection, `sitecustomize`, import interception, monkeypatching, wildcard evidence suppression, or operator interaction.

Startup, readiness, workload, expected-status, required-artifact, graceful-shutdown, forced-shutdown, cleanup, PID, serialization, and profile-integrity results remain independently typed. A missing, empty, malformed, truncated, unreadable, or PID-mismatched profile is failed evidence. Requested but unavailable thread/subprocess coverage, unresolved source normalization, incompatible identity, or bounded analytical omission is partial evidence. Portable output redacts secrets and physical paths while local manifests retain the minimum physical provenance required for audit. Generic runtime categories come only from deterministic sorted configuration rules; provider code contains no MLXForge, model, MLX, database, web, or framework-specific classifications. See [cprofile-runtime-analysis-specification.md](cprofile-runtime-analysis-specification.md).

Graphviz is an optional projection renderer. Missing `dot` is an explicit unavailable executable error and cannot produce a successful empty SVG/PNG. Optional tool availability is visible through `doctor` and `providers`.

`doctor` and `providers` report local installation paths and versions for both Tree-sitter distributions. Portable reports retain only bounded parser identity. If JavaScript source is selected while the grammar is unavailable, source and language-front-end records are unavailable/failed, the report is partial, and the command returns `ENODATA`; a Python-only run does not import or require the optional distributions.
## Standalone pstats caller evidence

Offline ingestion accepts both stdlib `profile.Profile` integer caller counts and cProfile `(total calls, primitive calls, self seconds, cumulative seconds)` caller tuples. Frame records retain their different `(primitive calls, total calls, self seconds, cumulative seconds)` ordering. Stdlib integer-zero frame timings and empty builtin filenames at line zero are valid. Booleans, negative counts/timings, nonfinite timings, invalid shapes, and unsupported caller representations remain invalid.

Integer caller records provide total counts only: primitive counts and edge timings are null, not zero or inferred from frame timings. Sanitized pstats retains integers as integers and cProfile tuples unchanged, and reload verifies graph identities and metrics. Caller-only references are preserved within explicit bounds without synthetic frame measurements.

Bare pstats does not authenticate its producer; the report records `producer=unknown` regardless of individual caller representations. Controlled cProfile collection records its known producer. Unknown or mismatched producer evidence prevents claim-eligible comparisons; integer-only edge timings remain explicitly unavailable in diagnostic comparisons. Captured frame timings do not establish wall duration, GPU time, unprofiled throughput, or qualification of a serving workload.

Invalid caller representation returns `EBADMSG` with a specific safe message. Worker memory exhaustion or signal termination returns `ENODATA`; deadline expiry returns `ETIMEDOUT`. Existing byte/frame/edge bounds, isolation, source non-execution, and collision checks remain in force.
