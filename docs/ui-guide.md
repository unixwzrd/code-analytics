# Web and terminal usage

Task-oriented controls for saved evidence. For exact arguments and automation guarantees see the [CLI reference](cli.md); for workflows and their outputs see [examples](cli-examples.md). This guide does not imply completion of every Phase 5 capability.

## Choose a workflow

The stop control belongs to standalone CLI-launched servers. A browser handoff opened by the TUI remains TUI-owned; return to its owning terminal to close that handoff. Missing server-control metadata is localized and does not block report navigation.

Bare `code-analysis` and `code-analysis ui` start or reopen a compatible background server and return your shell prompt. On macOS the browser opens automatically. Use **Stop Code Analysis** in the header to stop this session for all connected tabs; active jobs require explicit cancellation confirmation. Closing or reloading a tab leaves the server and jobs running. From the same collection-root directory, `code-analysis ui-stop` stops a single matching background session; use the printed `--session ID` if several match, and `--cancel-jobs` only when cancellation is intended. `ui --foreground --no-open` retains terminal-controlled use. Private server logs and session receipts are under `~/.cache/code-analysis/ui/`; protect their capability URLs. Startup does not scan code or create a project workspace.

After this server accepts **Stop**, the initiating page ends its UI session, cancels pending view requests and attempts to close its tab. Browsers generally allow script-opened windows to close; ordinary tabs may refuse. In that case a noninteractive **Code Analysis session closed** screen replaces the application, explains that server cleanup may still take a few seconds and tells you how to start again. Back/Forward cannot revive that page's controls. Cancelling the confirmation or receiving a shutdown error leaves the application available. Other connected tabs lose server access; their windows are not forcibly closed. This does not automate the browser or change its permissions.

For a first investigation, choose a project and collect/open static evidence, check provider/diagnostic health, then follow a finding or candidate into its evidence and verified source. Use runtime collection only for a specific execution question with explicit authorization. Compare retained compatible runs after a change; changing a table or graph does not require rescanning. Source browsing needs an explicit matching source root, while saved analytical views do not.

The sidebar groups existing analytical views by task. Overview offers one primary next step based on selected evidence, with other collection/investigation choices and expandable exact context. Global Help and each view's guide link open bundled documentation without replacing the analytical view. Search matches document titles and headings, not full text. Project profiles, tutorials and storage management remain deferred. Human first-use walkthrough acceptance remains outstanding.

Page help shows the relevant guide section, not the whole manual. **Browse full documentation** opens its complete reference; explicitly selecting a document does the same. The table of contents reflects the displayed scope, while title/heading search searches the complete bundled catalog. Internal guide links stay in the panel; external links open separately only when activated. Previous/Next help topic controls retain section/full-document history. Escape closes help, preserves the search query and restores focus. Reopening global Help restores the last scope and reading position within the tab. Help loading errors have their own retry action and do not change collection health or prevent analytical navigation.

Begin with **Overview** even if no evidence is loaded. Its primary action is **Analyze code** for an empty configured session, **Investigate findings** or **Explore modules** for saved static evidence, **Check collection issues** for required missing/failed evidence, or **Explore Python profile** for profile-only evidence. **Open saved runs**, Python profile collection/import and further investigation choices remain secondary routes. Navigation initially opens Project & collection and the accepted destination's group; groups can then be collapsed independently without losing other choices. An unavailable destination explains its prerequisite and offers a corrective action instead of making an unsupported request.

### Your first investigation

If Overview already identifies a static report, start at step 3; you do not need to collect it again just to explore the UI. Otherwise, try the tool on Code Analysis Suite's own `src` directory first:

1. Choose **Analyze code** on an empty Overview. Check the collection root under **Execution host and exact collection paths**. Leave **Operation** at **Static analysis (scan)**, set **Target path** to `src`, and keep the default language and strictness. `src` is relative to that collection root, not an arbitrary project elsewhere on the server.
2. Choose **Build command** and review the displayed command. If managed collection is enabled, confirm the reviewed command/workspace writes and choose **Run reviewed command**. When a verified result is available, choose **Open verified result**. In preview-only mode, copy the command and run it in your terminal instead. Static collection reads code without executing it; it writes local analysis artifacts.
3. Open **Diagnostics** to understand recorded gaps before interpreting the findings. Partial evidence is not the same thing as a broken UI or an empty analysis.
4. Open **Findings**, select one warning, and read its explanation and supporting evidence. Choose **Browse code at this source** if matching source access is configured; otherwise the saved evidence remains usable without source preview.
5. Use **Return to Findings** to return to the same filters and page. That completes the first investigation loop. Explore **Candidates** afterwards; leave runtime profiling and **Comparison** until you have a specific execution question or a second compatible run.

Project profiles and an interactive tutorial are not implemented yet. This short route explains the existing controls; it does not automatically choose a project, collect evidence or authorize refactoring.

### Evidence readiness

| Readiness | Meaning for this view and scope |
| --- | --- |
| Available | Required saved evidence is validated and complete, including legitimate zero findings. |
| Missing | Required evidence or a capability was not collected, is disabled or is unavailable. |
| Partial | Usable evidence exists but required coverage is incomplete, truncated or unresolved. |
| Failed | A required input or analytical contribution failed; do not interpret it as an empty result. |

Original report completeness and provider diagnostics remain authoritative. Optional gaps do not alone make complete core evidence unhealthy, although an optional capability may be required by a particular view. A configured source-preview root does not prove that current source matches the saved collection.

**Help** opens a toolkit-owned side panel. Choose a document, follow its table of contents or search topic titles/headings; Previous/Next help topic controls retain bounded tab-local history. **Expand help** provides full-width reading; **Close help** or an unmodified Escape returns focus to the invoking control. The underlying view stays mounted, retaining filters, jobs and drafts. Installed help is offline and does not require Markdown tooling. A help error offers retry without changing evidence readiness or blocking navigation.

Collection forms retain ordinary settings only in the current tab. Less frequent choices appear under **Advanced settings**, with a visible summary outside it. Leaving and returning clears execution acknowledgment, launch confirmation and the validated command preview; review a freshly built command before confirming anything. Reloading the page does not restore project settings. Server-owned running jobs remain reconnectable.

## Review findings

Open **Findings** after loading static evidence. Filter by severity, category, language or rule, then select a finding title to inspect its saved explanation and evidence. Follow a proven source target through **Browse code at this source** when matching source access is enabled. Close the evidence dialog to return to the retained selection. A legitimate zero count is different from absent or failed collection; check Diagnostics before treating silence as clearance.

## Understand state and effects

Use **State / effects** to inspect recorded mutation, lifecycle and validation evidence. Keep observed syntax, inferred relationships and execution outcomes separate. Missing providers or incomplete collection limit conclusions; a static state transition is not proof that a workload executed it. Open recorded evidence before deciding whether a boundary needs changing.

## Contracts and dictionary shapes

Use **Contracts** for recorded boundary contracts and **Dictionary shapes** for shapes, key access and flow evidence. Inspect exact subjects, resolution and uncertainty rather than treating every similarly named key as the same contract. Missing language/provider capabilities stay unavailable. Follow evidence into the source browser only with explicitly configured matching source; viewing these saved tables never rescans the project.

## Inspect clones and commonality

Use **Clones** to review duplicate-behavior and commonality evidence from the selected report. Similarity is a nomination, not an extraction decision. Review shared dimensions, ownership, call context, counter-evidence and omissions before moving to Candidates. Unsupported or missing analysis is not a zero-clone result.

The Modules column shows a short single identity directly, or a **recorded modules** disclosure with its exact count. Expand it to read the complete identities, wrapped within the column rather than a second horizontal scroll area. Expansion changes presentation only: scope filters still retain the complete matching cluster and all its members.

## Understand test impact

Use **Test impact** to inspect saved test discovery, coverage and affected-subject evidence. Static relationships suggest investigation; recorded coverage only describes its captured workload and source identities. Missing coverage, incomplete discovery and unmapped subjects must remain visible. No test executes when this view is opened; collection requires a separately confirmed operation.

## Review refactoring candidates

Use **Candidates** to inspect proposed opportunities, then open the ranked worklist or a review packet. Review eligibility, evidence, behavior differences, cost bounds, owner alternatives and qualification gates. Local decisions are attached explicitly and bound to the report and ledger identities. A candidate, ranking or packet is not authorization to edit source or execute a workload.

## Compare saved runs

Use **Comparison** after selecting compatible baseline and candidate evidence explicitly. Verify which side is which and inspect identity/configuration differences before interpreting added or removed findings. A changed finding count alone is not proof of improvement; compare completeness and provider health too. Loading or changing comparison sides does not collect new evidence.

The top of the view labels Baseline and Candidate with their portable target, completeness and SHA-256 prefix; expand **Exact report identities** for the full hashes. A row's **Source choices** opens an inspector above the results, not below a long table. **Return to selected row** restores that row's keyboard focus, page, filters and table/viewport position, including after column reordering; if you hide the Source column, focus returns to Apply comparison filters. Source selection itself reads saved evidence only; use **Preview baseline** or **Preview candidate** explicitly to request hash-verified current source. Preview lines wrap and flow with the page rather than requiring an inner scroll area. Missing source access remains an explanation, not an empty preview. Editing filters or leaving the view cancels pending inspection results.

## Check evidence health

Use **Providers** to understand optional capability availability and **Diagnostics** to inspect the selected report's recorded failures, gaps and omissions. Installed provider availability is not proof that it contributed to this saved run. Core evidence may be usable with optional gaps; a particular view may still require the missing capability. Correct a prerequisite by choosing evidence or explicitly planning collection, never by assuming missing evidence means zero results.

Providers displays the saved run, not a live installation check (`code-analysis doctor` supplies the latter). Short observations appear directly; longer or multiple observations use a **recorded observations** disclosure with the original count and exact text. Expand it with the pointer or keyboard. Unavailable providers keep their recorded state, even when they have no observations.

### Recover storage with today's tools

Use `code-analysis workspace list PATH` to inspect an owned workspace, pin a baseline with `code-analysis workspace pin PATH GENERATION_ID`, then preview `code-analysis workspace prune PATH --dry-run`. Review the targets before running without `--dry-run`; pruning deletes evidence, not just display preferences. The [CLI reference](cli.md#command-workspace-prune) defines exact options. Preserve important baselines and inputs explicitly; existing retention is not a complete cross-artifact reference tracker. Loose qualification output and derived indexes outside workspace generations need separate verified cleanup. A storage preview/management screen is planned, not implemented.

### Code browsing and session draft editing

The [current scope and roadmap](roadmap.md) track this follow-up. **Browse code** provides a saved-file/entity outline, focused relationship map, verified original source and recorded details. Select a file, then an entity; select an original-source line to inspect its innermost recorded declaration, or choose among equally specific matches. Back/Forward restore recorded selections. On narrow screens, use the three pane buttons to switch between files/entities, relationships and original source. Multiple evidence files are explicit choices, and paging preserves off-page parent identities. Evidence dialogs also offer **Browse code at this source** to open the same verified browser.

Back/Forward also restore the selected visible pane. Keyboard activation of a file/entity or original line opens the verified-source pane; delayed cancelled selections cannot take it back from a later pane choice. Pane switching retains valid in-flight evidence for the same selection rather than cancelling it. History contains only named report/selection/display metadata, never source or draft text. An active outline response with a mismatched report or selection revision displays an explicit error instead of an endless loading message.

When opening source from a finding or another saved-evidence view, **Return to Findings** (or the originating view) restores its filters, page and evidence-button focus. Browser Back/Forward also retain the investigation and selected original-source position. This context is tab-local and invalidates when the selected report/run binding changes. Dirty-draft and active-composition guards still apply; opening Help does not switch the source document or replace the editor.

Use **Relationship layer** to switch between containment, imports, recorded callee names, static call-site containment, dictionary flow and saved runtime calls. These are different kinds of evidence, not interchangeable ownership or runtime claims. Maps retain at most 100 nodes and 250 edges and disclose original, retained and omitted counts. Click a source-bound node, or focus it and press Enter/Space, to display its source immediately; no extra source button is needed. Nodes without exact source targets remain inspection-only and explain why. Containment nodes offer **Collapse children**, and **Expand all retained nodes** restores hidden descendants; this display operation does not delete analytical evidence. The accessible relationship table retains exact relationship, resolution and confidence values. Unsupported selections show an unavailable explanation rather than falling back to the whole project.

The runtime layer requires an explicitly loaded saved profile bound to the selected static report and matching captured source hashes. It shows observed caller/callee relationships, profile/workload identities and the focused neighborhood's bounds, not exhaustive program or thread coverage. Native or otherwise unmapped frames remain observed-only nodes without fabricated source links. **Browse recorded frame source** in ordinary runtime tables and graphs opens the same browser using a proven logical path and line; a recorded name alone cannot bind a frame. Missing edge timings remain unavailable. No workload is launched and no source is rescanned by either action.

If source is not connected, selecting a graph node or entity offers **Connect source folder** at the point of use. This prompt appears at most once per browser-view visit; cancelling keeps the selected entity and saved relationships available. **Connect source folder to show code** stays directly in the empty source pane, so you do not need to scroll to the top to retry. Use **Browse source folders** to choose the project directory inside the displayed collection root, confirm read-only access, then choose **Connect and display source**. The already-selected method or function appears automatically and focus returns to its source pane. If the recorded path is `src/reception.py`, select the folder containing `src`, not `src` itself. The server verifies a saved file hash before accepting the folder and checks each displayed file again. Wrong/changed source produces an actionable error, never a successful empty preview. Connecting does not rescan, create a workspace or enable execution. `--source-root PATH` remains an optional startup alternative, not a requirement for normal UI navigation. A session started without collection browsing needs that flag, or a restart with `--collection-root PARENT_FOLDER`; imported reports cannot authorize arbitrary filesystem access.

**Read README.md** appears when a readable README exists beside the selected file or in its ancestor folders. Open it to read the tutorial's assignment, then follow the offered local text links to its walkthrough or optional hints. Solutions are explicitly labeled as spoilers. This project reader uses the existing LocalOps content panel and retains code selection while open; Escape returns focus to the invoking button. Previous/next document controls retain up to 50 entries in this tab. Text is displayed literally, including Markdown notation, rather than executing or rendering target HTML. Only Markdown, reStructuredText and plain text are supported initially; binary documents, external content and embedded images are not loaded. Files are limited to 128 KiB; document/link omissions are disclosed. These are current project documents, not hash-bound evidence from the analysis run, and they never join the analyzed-source inventory or report exports. Changed documents require reopening their list rather than displaying stale content.

Changed source shows no text. Select **Edit draft** to load the complete hash-verified original explicitly; see the [current scope and roadmap](roadmap.md) for exact snapshot boundaries. Drafts are labelled **Draft—not analyzed**, show their logical path/report/source identity, and do not change saved findings. Original-span highlighting is disabled while a matching draft is dirty; the verified original remains below the draft. On narrow screens, scroll the source pane to reach the editor and original.

At most eight documents stay in session memory. **Open draft** restores text and selection; switching/reopening resets editor history, which is disclosed. **Close draft** frees its slot and asks before losing dirty text. **Discard draft** requires confirmation. Switching files or collections warns about dirty drafts, and IME composition must finish before navigation. Leaving or refreshing warns when drafts are dirty; a lost session cannot recover them. No repository save, autosave, persistent drafts or automatic analysis/execution is added.

Use **Copy** or **Export** explicitly. Export downloads a separate `.txt` file using original LF/CRLF and final-newline settings. Conflicting runs of trailing blank lines produce an error rather than silent removal. Mixed/bare-CR originals remain read-only and export unchanged. Hardware IME and human usability remain manual-review work; synthetic composition tests are not proof of OS/hardware behavior.

### Shared LocalOps controls

The Web client uses hash-pinned LocalOps UI Kit native shell, light/dark theme tokens, primary report tables, CodeEditor and ContentPanel assets. On narrow screens, use the navigation toggle to open Report views; choosing a view closes the drawer and focuses its heading. Escape closes an open drawer and returns focus to the toggle. Tables provide Columns controls for visibility, order and resizing, while report ordering and paging remain backend-owned. Column layout is currently local to the displayed table, not a persisted preference. Graphs, collection forms, evidence content and analytical state remain application-owned; bundling other toolkit components does not mean they are adopted.

### Access from another machine

Phase 5 keeps the server bound to localhost. Run the UI on the host holding the reports with browser auto-opening disabled, then use an operator-managed SSH local forward to its printed port. For example, if the server prints port 8765, run `ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 USER@HOST` on your browser machine. Open the server's printed localhost URL through that forwarded port, preserving any session fragment. Keep the URL/token private. This uses existing SSH authentication; Code Analysis does not configure SSH or expose a network listener. Paths, configured roots, collection and workloads still belong to the server host. Collection remains separately opt-in and confirmed. Direct network serving is deferred; do not bind the forward to all interfaces.

In the Web **Findings** table, scroll horizontally for metadata columns. Long explanations and suppression reasons use native disclosure controls: focus the summary and press Enter or Space, or click its arrow, to read the complete text. Collapsing a cell only changes presentation; saved findings, exports and evidence remain unchanged. Short inline text is not clipped. Click a finding's title to inspect its saved evidence.

### Read and navigate a graph

Web Architecture, dependency investigations, Explore graphs and runtime call graphs share **Zoom out**, **Zoom in**, **Fit overview** and **Actual size** controls. Graphs start at 100% with 14-pixel labels and scroll inside their viewport rather than shrinking automatically to fit the page. Zoom ranges from 50% to 300%; Fit overview can shrink further and explicitly warns that labels may become small. Actual size restores 100%.

Tab to the graph viewport to use native keyboard scrolling, or tab through its nodes; focused nodes scroll into view. Node selection and evidence navigation remain unchanged. Display controls make no analytical request and do not change selected identities, bounds, completeness or downloaded artifacts. Use the relationship and node tables for exact labels and dense relationships; zoom does not eliminate overlapping graph edges.

Architecture places shortened module labels in side columns outside the node ring. Dotted lines connect labels to their nodes; they are display guides, not additional dependency edges. Full module identities remain available through the node's accessible label and details.

### Focus subject-level finding totals

In Web **Explore evidence**, choose **subject findings**. Enter dotted module prefixes or rule IDs one per line, and select categories or severities. Repeated values are ORed within a control; different controls are ANDed. The backend filters individual findings before recalculating each subject's totals, category/rule counts and unique evidence count. Downloads use the last displayed selection, not unsaved form edits.

Exact subject IDs may be combined with category, severity and rule filters; selected subjects remain visible with zero totals when no findings match. Exact IDs cannot be combined with module prefixes. This projection currently has no language-filter implementation, so its language control is disabled and nonempty saved language scopes fail explicitly. Malformed saved filters also block the view and downloads until you explicitly reset or correct them. The separate Findings inventory retains its language filter.

In terminal **Static views**, choose **subject findings**, then press **Ctrl+F** or select **Finding filters**. The scrollable editor offers module prefixes, categories, severities and rule IDs. **Ctrl+S** applies the selection, **Escape** cancels, and **Reset** immediately applies an unfiltered selection. Search, paging and exports retain the applied filters; switching projection clears them. The scope line discloses filtered findings without subject identities, and **F2** shows the exact request and limitations. Indexed exact-subject selection and language filtering are not supported and are rejected explicitly. Rebuild older browsing indexes from saved JSON to add the retained finding facts; browsing does not rescan source.

### Inspect recorded callee relationships

Choose **lexical call graph** in Web **Explore evidence**, or the recorded lexical callee view in terminal **Static views → Graphs**. This shows each unique callee name saved for a function, not individual call sites. Exact same-language subject-name matches link to saved declaration evidence. Unknown or ambiguous names remain visible but have no invented source location. The relationship table retains resolution state and evidence IDs; unresolved-call totals are explicitly scoped to language-selected profiles before neighborhood/display bounds. A zero unresolved count does not prove complete resolution across providers.

Use the normal language, exact-node, module/package grouping and size controls, then export the current view or use terminal Ctrl+W for Web handoff. Missing function profiles are unavailable; regenerate an index to add this view to an older prepared cache. No target code is read or executed to render it. Runtime call graphs remain distinct measured evidence.

### Inspect individual call sites

Choose **static-call-sites** or **static-call-graph** in Explore evidence or terminal Static views. Unlike the lexical call graph, these retain individual recorded invocation spans, including repeated calls and dynamic callees with no known name. The graph links a source file to its recorded call sites; it is a containment view, not a claim about which function runs. Selecting a call site opens its saved invocation evidence rather than substituting a declaration location.

Calls retain language, source identity, evaluation context and conditional/deferred uncertainty. Complete syntax collection is not proof of runtime dispatch or execution. Missing, failed and truncated collection stays visible; saved-report views do not recollect it. Source previews still require an explicitly configured source root and matching bytes. Older draft reports without the current contract are not migrated automatically.

### Focus the candidate worklist

From **Candidates**, choose **Review ranked worklist** (Web) or **Review worklist** (terminal). This opens the existing policy-driven view, not a second ranking implementation. Inventory search and scope filters are preserved for your return but deliberately not translated into worklist policy. The Web **Return to candidate inventory** action restores that selection and focus; closing the terminal worklist returns to the unchanged inventory.

Use **Inspect candidate** on a Web worklist row, or Enter on a terminal row, to open its saved review packet. Closing the packet preserves worklist policy, page and explicitly attached decisions. Packets show static analytical evidence, not live maintainer decisions or authorization. Web requests and continuations bind the originating canonical report and optional ledger hashes; terminal reads use the exact current indexed row/page and revalidate any attached ledger. Changed selections cancel pending packets. A changed ledger requires explicit reselection rather than silently changing the evidence under review.

In **Explore evidence**, select **candidate worklist** to use the authoritative candidate filtering and ranking policy. Enter include/exclude module patterns one per line; matching is case-sensitive against the full logical module name, repeated patterns are ORed, and exclusions win. Combine these with candidate states, candidate kinds, language, cross-module-only, production-only and minimum shared dimensions. Production-only means outside the test modules discovered in the saved report, not proof that discovery was exhaustive. **Prefer an existing recorded owner** changes ranking, not eligibility. Filters apply before ranking and the **Records** bound. CLI `candidates --kind` and candidate-worklist `export --kind` use the same bounded kinds, which are also supplied by the backend to the Web controls.

The displayed individual ranking dimensions, evidence, partiality and omissions are retained in JSON, TSV and Markdown downloads. Editing controls invalidates the previous view and its downloads; choose **Show evidence** again. **Reset candidate filters** clears only the worklist policy. Switching to another evidence view disables these filters. Exact identity, neighborhood depth and graph-collapse selection are not applicable to the candidate worklist.

Workspace decisions are detached by default; report-only `undecided` is not proof that no local decision exists. In the Web worklist, choose **Use workspace decisions** to explicitly attach the selected owned workspace's saved ledger. The status displays its record count and exact ledger/report hashes, then enables **Decision states**. Unchanged rejected candidates are suppressed by the existing default worklist policy; select their rejection state to inspect them. **Clear decision selection** restores the report-only view. Switching evidence views or runs clears the attachment. Missing ledgers remain unavailable and are not created.

Every decision-aware view and download rereads and verifies the same ledger/report identities. If either changes, refresh/reselect explicitly; stale results are not silently rebound. These controls are read-only and cannot record decisions or authorize refactoring. The primary Candidates inventory remains separate from this richer worklist policy view.

In the terminal, open **Static views** (Ctrl+G) and choose **Candidate Worklist** when it is present in the prepared index. Press Ctrl+F or **Candidate policy** for the scrollable policy editor; Ctrl+S applies, Escape cancels. Languages, states and kinds allow multiple choices. Module patterns are entered one per line. The same filters and ordering run over strict named facts stored in the index, not source or a reopened report. Apply starts at the first page, and paging and Ctrl+E exports retain the exact policy. Rebuild older indexes to prepare these facts. No worklist is offered when the saved report has no candidate evidence; this does not erase the report's underlying findings or admission funnel.

For terminal decision-aware review, select **Use decisions** (Ctrl+D) in the worklist. This attaches only the explicitly configured owned workspace's ledger and enables decision choices in **Candidate policy**. **Decision identity** shows both complete SHA-256 identities and record count; F2 opens the current projection's completeness, bounds and full limitations. **Clear decisions** restores the report-only worklist. The prepared index retains canonical candidate reconsideration signatures and logical target identity, not ledger records or private reasons. Page requests and exports reread and verify the selected ledger; changes require reselection. Browsing never reopens the source report to reconstruct a signature. Missing workspace/ledger evidence stays unavailable, and switching away from the worklist clears the attachment. Rebuild older disposable indexes before using these controls.

### Browse package and module hierarchy

For recorded declarations, choose **symbol graph** in **Explore evidence**. Each edge means only that the saved module records that symbol. Select a node with Enter/Space or the pointer to inspect its saved span; source preview remains separately opted in and hash checked. Language and exact-identity selections apply before graph display bounds. Nested declarations remain module members: the view does not infer lexical parents, inheritance, calls or runtime ownership from names. Duplicate navigation identities fail explicitly rather than merging declarations. Existing JSON/Markdown/DOT/Mermaid/SVG/PNG/HTML downloads use the same saved projection.

Choose **hierarchy** in **Explore evidence** for an expandable saved package/module tree. Open or close branches with the pointer or Enter/Space on their disclosure control. Select a module button to inspect its recorded symbols and source evidence. A real package module may both contain children and offer its own source button; a grouping-only package has no fabricated source declaration.

Python grouping follows dotted module identities; JavaScript and Ruby grouping follows POSIX directory components and retains the full filename extension. The **Language** filter is applied before construction. **Records** bounds the retained tree with parents before children, and truncation remains visible; the graph-only node/edge budgets do not change this hierarchy projection. Existing JSON, Markdown, DOT, Mermaid, SVG, PNG and HTML downloads remain available. No source scan is performed during expansion or navigation, and source preview still needs separate permission and matching bytes.

### Inspect saved coverage in the terminal

Open **Static views** (Ctrl+G) and select **Coverage files**, **Coverage matrix** or **Uncovered proposal subjects** when that evidence was prepared. File rows retain binding state and saved line/arc/context counts. Matrix rows are sparse subject/context cells with named metrics and evidence identities; they are not an expanded subject-by-context grid. Counts are saved observation totals associated with context labels, not independently measured per-context execution counts. Null metrics stay null. Proposal subjects without linked qualification evidence are **qualification-unresolved**, not proven unexecuted; the view never authorizes changes.

Search applies before paging. Enter inspects the exact typed row; Ctrl+E exports the current selection as JSON, TSV or Markdown. Missing coverage does not create an empty successful view; the corresponding choice is unavailable. Source partiality, unbound coverage and preparation/export omissions remain visible. Rebuild older disposable indexes to prepare these optional views; browsing and exports do not reopen report JSON or target source. Static **Test impact** remains a separate likely-reference view and is not execution coverage.

### Inspect lifecycle roles and conversion sites

In **Explore evidence**, choose **structure lifecycle graph** to inspect recorded construction, ownership, production, access, mutation, serialization and alias roles. Recorded dictionary states are observations attached to their shape, not a temporal state machine: the report does not prove a transition between two observed values. A structure and shape with the same recorded owner are an association, not proof that two values are identical. The original lifecycle table remains available for lifetime, cleanup, concurrency and unresolved observations.

Choose **conversion graph** for saved conversion/serialization edges. Each observed site retains its actual source and target, confidence and evidence; repeated sites between the same subjects remain separate. These arrows are static data-flow observations, not proof that a conversion ran or succeeded. Select a recorded node to navigate to its evidence; source preview still requires separate permission and matching source bytes.

Both views share the existing record/node/edge limits, exact-selection neighborhoods, partiality and download controls. JSON, Markdown, DOT, Mermaid, SVG, PNG and HTML exports use the same saved-report projections as CLI `export --projection structure-lifecycle-graph` and `export --projection conversion-graph`. Graphviz is required only for SVG/PNG rendering, not for analysis or browser navigation. No diagram reads target source during construction.

### Inspect complexity and ownership-role heatmaps

In **Explore evidence**, choose **complexity** for recorded function metrics or **structure lifecycle** for recorded structure-role counts. Heatmaps supplement the authoritative table; they do not change report ordering, selection, bounds or downloads. Physical LOC, branches, nesting, arguments and cyclomatic complexity are separate metrics, not a combined quality score. Structure-role counts describe the recorded producers, readers, writers, mutators, serializers, aliases and conversions, not proven runtime ownership or lifecycle ordering.

Read each column's legend independently: six linear color bins are scaled over its retained rows, not the entire codebase or an external acceptance threshold. Filtering or changing the record bound can therefore change colors without changing any value. A constant-zero column uses the lowest shade; equal nonzero values share a midpoint shade without implying a ranking. Exact numeric values remain visible; absent values are unavailable, not zero. Source partiality and truncation remain displayed above the view. Toggle **Heatmap** / **Table** with keyboard or pointer; focus the named heatmap region to scroll wider tables. Expand **Evidence limitations** to read the original report limitations. Existing JSON/TSV/Markdown downloads retain the saved projection contract.

### Follow graph nodes to recorded evidence

In Explore graph views, click a node or focus it and press Enter/Space. The backend checks that the node belongs to the exact displayed projection and resolves its recorded source identity. Contracts, structures, interface endpoints, tests and fixtures now open their saved evidence spans as well as the existing module, symbol, subject and state nodes. Test-module navigation shows recorded test/fixture/relationship sites, not an invented whole-file declaration. Clicking does not overwrite the form's exact-selection field, because each projection has its own selection policy.

Unresolved targets and logical groups without proven source locations display an explicit unavailable message. This does not create a source span or erase report partiality. **Preview source** remains separately opted in, confined and hash-checked; navigation itself reads only saved report data.
