# Development

## Public source and private evidence

The public beta starts from a reviewed source snapshot. Original development history, internal coordination and machine-specific qualification records are archived privately; do not merge that archived history into public branches. Keep local workspaces, captures, credentials and operator notes outside tracked source. `.gitignore` prevents ordinary additions, not exposure of files already committed or force-added. Review the staged tree, source archives and release assets separately, including Git history before changing visibility.

Synthetic fixtures, golden reports and the tutorial evidence are deliberately public. `tests/test_publication.py` verifies ignore-policy boundaries, beta metadata and all nine supplied tutorials' source hashes without executing their code. The source distribution includes tutorials; the installed wheel contains the application and compiled help, not a tutorial browser. Bounded credential-pattern scanning is not proof that arbitrary secrets are absent.

## Repeatable Web UI gate

Run `python tools/test_ui.py --smoke` during UI work and `python tools/test_ui.py` for full UI qualification. Both use the existing interpreter and installed Chromium/WebKit without installing dependencies, retain unique logs/JUnit/strict JSON receipts and reject skipped/empty/changed-input qualification. Local and CI selection share the same inventory. See [UI testing and usability review](ui-testing.md) for the coverage matrix, focused commands, artifacts, developer prerequisites and separate uncoached human walkthrough. This is a UI gate, not a substitute for the full analyzer suite or human acceptance.

UI lifecycle qualification uses `tests/test_web_lifecycle.py` plus CLI/display, collection-job, owned-TUI-handoff and offline-help regressions. Verify detached pipe/session isolation, concurrent reopening, private receipts/leases, native startup failures, target-package shadowing prevention, same-origin stop, cancellation consent and owner-disabled shutdown. Rebuild wheel/sdist from an archived candidate, test installed launch/reopen/stop and Chromium/WebKit desktop controls outside the checkout, and prove an empty collection root stays unchanged. Existing toolkit assets must remain byte-identical; no generic widget fork or package installation is implied.

## Bundled user help

The selected user documents are README installation/everyday-command excerpts, `docs/ui-guide.md`, `docs/cli.md`, `docs/cli-examples.md` and `docs/report-and-diagram-catalog.md`. They compile into five offline topics, not a second maintained manual. Excluded developer references are nonclickable in the bundle; plans, qualification records, private material and archives are not packaged as help. Review command and flag changes alongside the CLI reference, and check contextual topic anchors whenever a workflow changes.

Use `python tools/build_user_help.py --write` after intentional documentation/generator changes; regeneration requires the optional `docs` extra's exact `markdown-it-py==4.0.0`. Use `python tools/build_user_help.py --check` for a standard-library-only freshness and integrity check. Wheel and sdist builds run that check and fail on stale or missing assets; builds never regenerate silently. Runtime reading uses package resources, strict frozen metadata and a closed hash-validated asset allowlist, with no Markdown renderer or source checkout required. Help failure must remain local to Help and must not disable analytical views.

Use it for guided navigation/help, project setup, tutorials and storage tests; do not infer public-release readiness from automated browser qualification. Preserve exact LocalOps asset provenance and qualify additions independently. Help needs keyboard/touch coverage and a maintainer first-use walkthrough, not hover-only assertions.

## CI dependency boundaries

Use `python -m pytest -m 'not ui'` and `python tools/test_ui.py` for the disjoint full-suite gates. Module-based pytest invocation makes the checkout's `tools` namespace available consistently. Golden reports retain exact interpreter provenance, so CI pins Python 3.12.13 rather than rewriting recorded versions to match whichever interpreter happens to run. Other interpreter/platform compatibility needs separate qualification. CI provisions Graphviz for graphics checks and verifies Ruby/Prism; synthetic semantic-provider tests supply synthetic vectors and metadata without requiring an ML stack or downloading models.

Terminal/Web handoff gates cover `tests/test_owned_web_handoff.py` and `tests/test_ui_handoff.py`: exact canonical saved-report/subject identity, regular bounded input, no inherited collection/source permissions, explicit launcher invocation, path-only fallback, invalid replacement preserving the previous immutable snapshot, changed-path result rejection and shutdown preventing late background publication. Test real loopback HTTP lifecycle with synthetic artifacts; mock external browser launchers rather than opening user applications. A prepared index must not be substituted for its authoritative JSON report.

Trusted-interpreter collection checks include `tests/test_collection_interpreters.py`: no execution during configuration/preview, closed choice IDs, path-stable choices, launcher replacement rejection, analyzer/workload command parity, actual synthetic scan/profile generation binding, and incompatible-launcher failure without fallback. Preserve launcher symlinks because resolving them can change virtual-environment selection. Explicit trust does not certify an environment's package compatibility or isolate same-user executable replacement races.

Collection backend gates are `tests/test_collection_commands.py`, `tests/test_collection_execution.py`, `tests/test_collection_artifacts.py`, and `tests/test_collection_jobs.py`, followed by `tests/test_collection_web_jobs.py`, full-suite and package checks. They use temporary synthetic projects and short tool-owned workloads only. Verify exact command parity, isolated analyzer imports, process/start ownership, cancellation/timeout cleanup, native statuses, private atomic job records, storage bounds, restart uncertainty and revalidation of exact retained generations. HTTP gates cover authorization, confirmation, tampering, cancellation, static/profile opening and checked logs; real Chromium gates cover desktop/mobile launch, reconnect and result opening. Optional psutil is required for managed process ownership, never silently installed.

Compact-storage changes must preserve full serialized analytical values after strict reconstruction, including null/boolean/numeric distinctions, all evidence identities, explicit language/state tags, configuration, summary counts and provider/section health. Pretty and compact inputs must normalize to the same canonical bytes. Regenerated projection goldens must be audited for identity-only changes when no analytical behavior changes; run the ordinary suite without regeneration helpers afterward. A changed canonical report hash must never silently rewrite or qualify a previous hash-bound receipt or runtime capture.

For saved-report UI measurements, use `python tools/measure_ui_service.py REPORT OUTPUT [--profile PROFILE]`. Run unprofiled before/after samples serially against the same retained input, compare every output identity before timing, and use cProfile only to explain changed work. The [current scope and roadmap](roadmap.md) records workload controls, accepted scope, and unresolved memory/loading limits.

The base-install job builds a wheel, installs it into a fresh virtual environment with only core dependencies, and runs `python -m unittest discover -s tests -p test_base_install.py -v`. These standard-library tests start isolated Python processes outside the checkout, prohibit optional imports, prove Python scanning and saved-report HTML/Markdown/UI services work without source access, and verify that selected JavaScript without a grammar remains explicitly unavailable and partial. They do not require pytest or its conftest.

The full-suite job installs `.[dev,javascript,runtime]` and configures Ruby 3.3.4 with Prism 1.9.0 because synthetic adapter/runtime tests exercise these providers. The browser job installs `.[dev,browser,runtime]` and Chromium for saved-report and synthetic managed-collection interaction checks. Optional-provider absence and presence are separate qualification responsibilities; success in a developer environment is not proof of a clean base installation. Local dependency installations are not authorized by the CI configuration. Remote CI and type-check results must be inspected before claiming those gates passed.

Runtime hardening adds `tests/test_runtime_lifecycle.py`, `tests/test_runtime_manifest.py`, and `tests/test_runtime_queries.py` to the focused gates. Synthetic loopback qualification executes only a local tool-owned HTTP fixture, never a consumer application. Descendant sampling is not a sandbox: tests prove PID/start-checked signaling and rejection of observed detached sessions, not exhaustive prevention of rapid fork/reparent escape. No performance improvement is claimed from these reliability tests.

Phase 4P focused checks are `tests/test_runtime_ingestion.py`, `tests/test_runtime_commands.py`, and `tests/test_profiling.py`, followed by Black, Ruff, available type checking, the full suite, and a clean snapshot build containing both tracked and new candidate files. Runtime tests use synthetic programs only. Real MLXForge runtime execution is prohibited; its historical `.prof` may be ingested read-only after internal checks. Current evidence and uncompleted gates are recorded in [current scope and roadmap](roadmap.md).

Use the qualification interpreter explicitly because command harnesses may sterilize `PATH`:

```bash
PY=/path/to/venvutil/bin/python
$PY -VV
$PY -c 'import sys; print(sys.executable)'
PYTHONPATH=src $PY -m pytest
```

Do not install or upgrade global or Conda packages implicitly. The repository may be installed into `venvutil` only when dependencies are already satisfied:

```bash
$PY -m pip install --no-build-isolation --no-deps -e .
```

A target beneath a configured source root uses the project-root `.code-analysis` workspace; `tests/fixtures/` is not treated as executable test source.

Golden fixtures live under `tests/golden/`; synthetic projects live under `tests/fixtures/`. Tests must not depend on MLXForge or the predecessor script and must not import fixture packages.

Saved-report `query` and `export` tests construct or retain synthetic JSON first, then operate only on that report. They must not receive a target source path or use discovery as part of rendering. Goldens cover authoritative JSON/Markdown plus TSV, DOT, Mermaid, and—when Graphviz is available—byte-deterministic SVG/PNG derivatives.

Phase 3 fingerprint cache entries are keyed by source SHA-256, logical module/path, analyzer version, Python version, and Phase 3 configuration identity. Cache payloads are strict frozen Pydantic records containing token/AST/statement fingerprint facts, never source text. A corrupt or mismatched payload is an invalidation and is recomputed; it cannot become evidence.

JavaScript normalized-fact cache entries additionally bind source language/syntax/module mode, parser and grammar identity, normalization version, and relevant configuration. They contain only strict typed normalized facts and hashes, never raw target source or Tree-sitter nodes. Python-only tests explicitly prevent imports of the optional parser distributions.

Ordinary CLI scans create `.code-analysis/` by default. Unit tests that are not exercising workspace behavior must pass `--no-workspace`; workspace tests use temporary synthetic projects. Generations are immutable and only the exact owned `latest` aliases may be symlinks. Never point a default-workspace scan at a read-only consumer repository. Use `--no-workspace` or an explicitly authorized external `--workspace` instead.

Runtime tests must use synthetic scripts or Code Analysis Suite itself. They require explicit `--allow-execution`, must not depend on MLXForge, and must verify owned-process timeout cleanup, environment filtering, stream hashing, source binding, and portable path removal. MLXForge tests, profiling, inference, conversion, daemons, and qualification remain prohibited.

The POSIX errno-based status contract is defined in [cli.md](cli.md): `0` success, `EPERM` denied execution/policy, `EINVAL` invalid input, `ENODATA` incomplete evidence, `EBADMSG` malformed/colliding artifacts, `EPROTO` unexpected provider/workload failure, `ETIMEDOUT` timeout, and `EFAULT` invalid internal boundary. Filesystem failures preserve their positive `OSError.errno`. Values come from Python's `errno` module and therefore follow the host C library. Authoritative JSON goes to stdout; diagnostics go to stderr.
