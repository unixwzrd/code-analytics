# Security and private reports

Static analysis parses target source without importing or executing it. Profiling and explicitly confirmed managed jobs execute Python with the operator's permissions; they are not a sandbox. Keep the UI on loopback. The current application does not provide a reviewed direct-network serving mode.

Do not put credentials, proprietary source, raw profiles, complete local workspaces or sensitive command lines into public issues. Portable reports can still reveal project names, identifiers, literals and architecture even when host paths are removed. Review every shared artifact.

For a potential vulnerability, use GitHub's private vulnerability reporting control **if it is available on this repository**. If it is unavailable, contact the [maintainer](https://github.com/unixwzrd) to arrange a private reporting channel; do not disclose exploitation details in a public issue. A private reporting channel must be confirmed before sending sensitive material. No response-time or remediation guarantee is implied by this prerelease.

Only the current beta candidate is under active development. Keep the original evidence, tool version and a minimal reproduction; do not run hostile projects without an external sandbox appropriate to your environment. Detection or a proposed refactor never grants permission to change source.
