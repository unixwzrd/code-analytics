Web and terminal usage

Task-oriented controls for saved evidence. For exact arguments and automation guarantees see the CLI reference; for workflows and their outputs see examples. This guide does not imply completion of every Phase 5 capability.

Choose a workflow

The stop control belongs to standalone CLI-launched servers. A browser handoff opened by the TUI remains TUI-owned; return to its owning terminal to close that handoff. Missing server-control metadata is localized and does not block report navigation.

Bare code-analysis and code-analysis ui start or reopen a compatible background server and return your shell prompt. On macOS the browser opens automatically. Use Stop Code Analysis in the header to stop this session for all connected tabs; active jobs require explicit cancellation confirmation. Closing or reloading a tab leaves the server and jobs running. From the same collection-root directory, code-analysis ui-stop stops a single matching background session; use the printed --session ID if several match, and --cancel-jobs only when cancellation is intended. ui --foreground --no-open retains terminal-controlled use. Private server logs and session receipts are under ~/.cache/code-analysis/ui/; protect their capability URLs. Startup does not scan code or create a project workspace.

For a first investigation, choose a project and collect/open static evidence, check provider/diagnostic health, then follow a finding or candidate into its evidence and verified source. Use runtime collection only for a specific execution question with explicit authorization. Compare retained compatible runs after a change; changing a table or graph does not require rescanning. Source browsing needs an explicit matching source root, while saved analytical views do not.

The sidebar groups existing analytical views by task. Overview offers one primary next step based on selected evidence, with other collection/investigation choices and expandable exact context. Global Help and each view's guide link open bundled documentation without replacing the analytical view. Search matches document titles and headings, not full text. Project profiles, tutorials and storage management remain deferred. Human first-use walkthrough acceptance remains outstanding.

Page help shows the relevant guide section, not the whole manual. Browse full documentation opens its complete reference; explicitly selecting a document does the same. The table of contents reflects the displayed scope, while title/heading search searches the complete bundled catalog. Internal guide links stay in the panel; external links open separately only when activated. Previous/Next help topic controls retain section/full-document history. Escape closes help, preserves the search query and restores focus. Reopening global Help restores the last scope and reading position within the tab. Help loading errors have their own retry action and do not change collection health or prevent analytical navigation.

Begin with Overview even if no evidence is loaded. Its primary action is Analyze code for an empty configured session, Investigate findings or Explore modules for saved static evidence, Check collection issues for required missing/failed evidence, or Explore Python profile for profile-only evidence. Open saved runs, Python profile collection/import and further investigation choices remain secondary routes. Navigation initially opens Project & collection and the accepted destination's group; groups can then be collapsed independently without losing other choices. An unavailable destination explains its prerequisite and offers a corrective action instead of making an unsupported request.

Your first investigation

If Overview already identifies a static report, start at step 3; you do not need to collect it again just to explore the UI. Otherwise, try the tool on Code Analysis Suite's own src directory first:

  1. Choose Analyze code on an empty Overview. Check the collection root under Execution host and exact collection paths. Leave Operation at Static analysis (scan), set Target path to src, and keep the default language and strictness. src is relative to that collection root, not an arbitrary project elsewhere on the server.
  2. Choose Build command and review the displayed command. If managed collection is enabled, confirm the reviewed command/workspace writes and choose Run reviewed command. When a verified result is available, choose Open verified result. In preview-only mode, copy the command and run it in your terminal instead. Static collection reads code without executing it; it writes local analysis artifacts.
  3. Open Diagnostics to understand recorded gaps before interpreting the findings. Partial evidence is not the same thing as a broken UI or an empty analysis.
  4. Open Findings, select one warning, and read its explanation and supporting evidence. Choose Browse code at this source if matching source access is configured; otherwise the saved evidence remains usable without source preview.
  5. Use Return to Findings to return to the same filters and page. That completes the first investigation loop. Explore Candidates afterwards; leave runtime profiling and Comparison until you have a specific execution question or a second compatible run.

Project profiles and an interactive tutorial are not implemented yet. This short route explains the existing controls; it does not automatically choose a project, collect evidence or authorize refactoring.

Evidence readiness

Readiness Meaning for this view and scope
Available Required saved evidence is validated and complete, including legitimate zero findings.
Missing Required evidence or a capability was not collected, is disabled or is unavailable.
Partial Usable evidence exists but required coverage is incomplete, truncated or unresolved.
Failed A required input or analytical contribution failed; do not interpret it as an empty result.

Original report completeness and provider diagnostics remain authoritative. Optional gaps do not alone make complete core evidence unhealthy, although an optional capability may be required by a particular view. Installed help is offline and does not require Markdown tooling. A help error offers retry without changing evidence readiness or blocking navigation.

Collection forms retain ordinary settings only in the current tab. Less frequent choices appear under Advanced settings, with a visible summary outside it. Leaving and returning clears execution acknowledgment, launch confirmation and the validated command preview; review a freshly built command before confirming anything. Reloading the page does not restore project settings. Server-owned running jobs remain reconnectable.

Check evidence health

Use Providers to understand optional capability availability and Diagnostics to inspect the selected report's recorded failures, gaps and omissions. Installed provider availability is not proof that it contributed to this saved run. Core evidence may be usable with optional gaps; a particular view may still require the missing capability. Correct a prerequisite by choosing evidence or explicitly planning collection, never by assuming missing evidence means zero results.

Access from another machine

Phase 5 keeps the server bound to localhost. Run the UI on the host holding the reports with browser auto-opening disabled, then use an operator-managed SSH local forward to its printed port. For example, if the server prints port 8765, run ssh -N -L 127.0.0.1:8765:127.0.0.1:8765 USER@HOST on your browser machine. Open the server's printed localhost URL through that forwarded port, preserving any session fragment. Keep the URL/token private. This uses existing SSH authentication; Code Analysis does not configure SSH or expose a network listener. Paths, configured roots, collection and workloads still belong to the server host. Collection remains separately opt-in and confirmed. Direct network serving is deferred; do not bind the forward to all interfaces.

In the Web Findings table, scroll horizontally for metadata columns. Long explanations and suppression reasons use native disclosure controls: focus the summary and press Enter or Space, or click its arrow, to read the complete text. Collapsing a cell only changes presentation; saved findings, exports and evidence remain unchanged. Short inline text is not clipped. Click a finding's title to inspect its saved evidence.
